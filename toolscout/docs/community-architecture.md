# קהילת תקומה: אפיון MVP

**המצב היום:** הקהילה עוד לא פעילה.
- האתר סטטי (Netlify), בלי שרת, בלי מסד נתונים ובלי חשבונות משתמשים.
- באתר מוצגים רק תחומי הקהילה, מסומנים "בקרוב", עם קישור ליצירת קשר למי שמעוניין. אין הרשמה מדומה.
- localStorage שומר מידע רק בדפדפן אחד, ולכן הוא לא מתאים לשום מידע משותף.

## 1. מה עובד היום ומה דורש שרת
| יכולת | היום | מה נדרש |
|---|---|---|
| תצוגת תחומי קהילה וכללי שיח | עובד (סטטי) | — |
| "ספרו לנו שאתם בעניין" | עובד: הקישור פותח את תוכנת הדואר של המשתמש, בלי לשמור מידע באתר | — |
| מועדפים | עובד בדפדפן אחד בלבד (localStorage). מסומן ככזה | חשבון, כדי לסנכרן בין מכשירים |
| חשבונות, פרופילים | לא קיים | אימות + מסד נתונים |
| פוסטים, תגובות, קבוצות, אירועים | לא קיים | מסד נתונים + הרשאות בשרת |
| דיווח, חסימה, ניהול תוכן | לא קיים | מסד נתונים + ממשק מנהל |
| הגנה מספאם | לא קיים | הגבלת קצב בשרת + CAPTCHA |

## 2. היקף ה־MVP
1. **חשבון:** הרשמה בקישור קסם לאימייל (בלי סיסמה). אפשר להוסיף Google בהמשך.
   - גיל מינימלי 16, עם הצהרה בהרשמה.
   - מחיקת חשבון עצמית.
2. **פרופיל:** שם תצוגה, ביו קצר, תחומי עניין (מתוך רשימת נושאי הספרים), אזור כללי (לא חובה) ונראות (רק אני / חברי קהילה / כולם).
   - **אין:** טלפון, כתובת או תאריך לידה.
3. **קבוצות:** ההתחלה עם הקבוצות מ־`data/communities.json`. רק מנהל יכול לפתוח קבוצה חדשה.
4. **פוסטים:** סוגים: דיון, שאלה, המלצת ספר. אפשר לקשר ספר, קורס או כלי מהקטלוג.
   - טקסט בלבד ועד 2 קישורים. בלי העלאת קבצים ב־MVP.
5. **תגובות:** שרשור ברמה אחת. מי שפרסם שאלה יכול לסמן תשובה כ"מועילה".
6. **דיווח וחסימה:** דיווח על פוסט, תגובה או משתמש, עם סיבה. החסימה דו־כיוונית.
7. **ניהול:** תור דיווחים, הסתרה, מחיקה, השעיה, ויומן פעולות מנהל.
8. **התראות:** סיכום שבועי באימייל, למי שבחר בו. בלי התראות דחיפה ב־MVP.

**מחוץ ל־MVP:** הודעות פרטיות, העלאת תמונות, אירועים פיזיים עם מיקום, ופיד מומלץ אלגוריתמי.

## 3. מודל נתונים
- **profiles:** id (= auth user), display_name, bio, interests[], region?, visibility, created_at, status (active / suspended).
- **groups:** id, slug, name_he, name_en, description, rules, visibility (open / members).
- **memberships:** user_id, group_id, role (member / moderator), joined_at.
- **posts:** id, group_id, author_id, kind (discussion / question / book_rec), title, body, ref_type?, ref_id?, created_at, edited_at, status (visible / hidden / removed).
- **comments:** id, post_id, author_id, body, helpful (bool), created_at, status.
- **reports:** id, reporter_id, target_type, target_id, reason, note, created_at, resolved_by?, resolution?.
- **blocks:** blocker_id, blocked_id.
- **mod_log:** id, moderator_id, action, target, reason, created_at.

## 4. הרשאות (נאכפות בשרת, למשל Row Level Security)
- משתמש עורך ומוחק רק את התוכן שלו.
- קבוצה במצב "members": רק חברים קוראים וכותבים בה.
- מנהל קבוצה מסתיר תוכן רק בקבוצה שלו. מנהל ראשי בכל האתר.
- משתמש חסום לא רואה את מי שחסם אותו ולא מגיב לו.
- משתמש מושעה קורא אבל לא כותב.
- **הרשאות לא נבדקות בדפדפן בלבד.**

## 5. הגנה מספאם
- **הגבלת קצב:** עד 5 פוסטים ו־30 תגובות בשעה לחשבון חדש, ופחות ב־7 הימים הראשונים.
- **CAPTCHA בהרשמה:** Cloudflare Turnstile, שחינמי ולא דורש עוגיות פרסום. צריך לאמת את התנאים לפני החיבור.
- **קישורים:** עד 2 בפוסט. לחשבון חדש אין קישורים ב־24 השעות הראשונות.
- **הסתרה אוטומטית:** תוכן שקיבל 3 דיווחים מוסתר עד בדיקה.

## 6. כללי שיח (בהתאם לקו המערכתי)
- **מותר ורצוי:** ויכוח נמרץ, ביקורת על רעיונות, ספרים ומדיניות, ועמדות שונות משלנו.
- **אסור:**
  - איומים
  - הטרדה ממוקדת
  - חשיפת פרטים אישיים (doxxing)
  - התקפה על אדם בשל זהותו (דת, מוצא, מגדר וכו')
  - הסתה לאלימות
  - ספאם
  - התחזות
- **עקרונות:**
  - עובדה, פרשנות ודעה מופרדות.
  - ציטוט מספר צריך מקור מדויק.
  - תוכן שנוצר ב־AI מסומן.
- **אכיפה:** אזהרה, הסתרה, השעיה זמנית, ואז חסימה. אפשר לערער פעם אחת.

## 7. פרטיות
- **מינימום מידע:** אימייל, שם תצוגה, ותחומי עניין אם המשתמש בחר.
- **בלי מעקב:** אין פיקסלים של צד שלישי באזור הקהילה.
- **שליטה בנתונים:** ייצוא ומחיקה של נתונים מתוך ההגדרות.
- **שמירה:** תוכן של חשבון שנמחק מוסר תוך 30 יום. יומן ניהול נשמר שנה.
- **לפני ההשקה צריך לעדכן:**
  - מדיניות הפרטיות: אילו נתונים נאספים, איפה הם מאוחסנים, מי ספק השירות, ובסיס חוקי לפי חוק הגנת הפרטיות ותיקון 13.
  - תנאי השימוש.
  - המסמכים הם טיוטה עד לבדיקת עורך דין.

## 8. השוואת תשתיות (מגבלות המסלול החינמי, נבדקו מול אתרי הספקים)
| | Supabase (Free) | Firebase (Spark) | שרת עצמאי (למשל Postgres + Node על VPS) |
|---|---|---|---|
| מסד נתונים | Postgres, 500MB | Firestore, 1GiB | ללא מגבלה מעבר לשרת |
| אימות | עד 50,000 MAU | עד 50,000 MAU | לבנות או להתקין לבד |
| תעבורה ושימוש | 5GB egress, 1GB אחסון קבצים | 10GiB/חודש; 50K קריאות, 20K כתיבות ו־20K מחיקות ביום | לפי השרת |
| הרשאות | Row Level Security ב־SQL | Security Rules | בקוד שלנו |
| מגבלות | פרויקט מושהה אחרי שבוע בלי פעילות; עד 2 פרויקטים; Pro מ־25$ לחודש | אין צורך באמצעי תשלום במסלול Spark | תחזוקה, גיבויים ואבטחה עלינו; עלות VPS חודשית |
| נעילת ספק | נמוכה: Postgres סטנדרטי, ייצוא מלא | גבוהה יותר: מבנה נתונים קנייני | אין |

**המלצה: Supabase.**
- Postgres והרשאות ברמת השורה מתאימים למודל הנתונים ולהרשאות שלמעלה.
- קל לייצא את הנתונים אם נעבור ספק.
- המסלול החינמי מספיק לפיילוט, ואפשר לחבר אותו לאתר הסטטי בלי לעזוב את Netlify.
- **סיכון:** השהיה אחרי שבוע בלי פעילות. בקהילה פעילה זה לא אמור לקרות, ולפני השקה רחבה כדאי לשקול Pro.

**מה דורש אישור שלך לפני שמתחילים:**
- פתיחת חשבון בשמך והסכמה לתנאים.
- בחירת אזור אחסון הנתונים (מומלץ אזור באירופה).
- עדכון מסמכי הפרטיות.
- החלטה מי ינהל את הקהילה.

## 9. סדר עבודה מוצע אחרי אישור
1. סכמה, RLS ובדיקות הרשאה אוטומטיות.
2. הרשמה, פרופיל ומחיקה.
3. קבוצות, פוסטים ותגובות.
4. דיווח, חסימה ותור ניהול.
5. הגבלת קצב ו־CAPTCHA.
6. פיילוט סגור עם קבוצה קטנה.
7. עדכון מדיניות.
8. פתיחה.
